# CPIMS+ AI — معماری مرجع انسان‌محور و حافظ حریم خصوصی

## وضعیت پروژه

این پروژه در حال حاضر یک **پروژه پژوهشی فردی، PoC مبتنی بر داده مصنوعی، و Overlay فارسی برای Primero** است.

هیچ داده واقعی کودک، خانواده، پناهنده، مددجو، بیومتریک یا پرونده واقعی نباید در این مخزن قرار گیرد.

## پیاده‌سازی فارسی Primero

در پوشه `implementation/` یک مسیر قابل بازتولید برای فارسی‌سازی نسخه متن‌باز Primero اضافه شده است. نسخه مبنا فعلاً `Primero v2.14.5` است.

Primero از قبل Locale دری `fa-AF` و پشتیبانی RTL دارد. Overlay این پروژه همه کلیدهای همان Locale را به‌عنوان ساختار پایه حفظ می‌کند، Locale جدید `fa-IR` می‌سازد، واژگان متداول را به فارسی ایران نزدیک می‌کند، آن را به فهرست RTL و fallback نرم‌افزار اضافه می‌کند و با QA خودکار بررسی می‌کند که کلید ترجمه‌ای از قلم نیفتاده باشد.

منظور از «پوشش کامل فارسی‌سازی» در این مرحله، **پوشش کامل کلیدهای رابط کاربری موجود در Locale مبنا** است؛ نه این ادعا که همه اصطلاحات تخصصی حمایت از کودک، حقوقی و پزشکی بدون بازبینی حرفه‌ای آماده Production هستند. بازبینی زبانی تخصصی همچنان یک Gate اجباری است.

پیکربندی رسمی CPIMS+ به‌صورت عمومی همراه کد Primero ارائه نمی‌شود؛ بنابراین این مخزن ادعا نمی‌کند Configuration رسمی CPIMS+ را بازسازی کرده است. Overlay برای اعمال روی یک نصب مجاز Primero/CPIMS+ طراحی شده است.

## ایده اصلی

پرسش مرکزی پروژه این است:

> چگونه می‌توان از هوش مصنوعی برای کمک به مددکار استفاده کرد، بدون آنکه هویت، داده، قدرت سازمانی و قدرت تصمیم‌گیری AI در یک نقطه متمرکز شوند؟

اصل بنیادی سامانه:

> **AI کمک می‌کند؛ انسان مسئول تصمیم باقی می‌ماند.**

## اصول معماری

1. هیچ بازیگر واحدی نباید تصویر کامل یک انسان را در اختیار داشته باشد.
2. داشتن Token یا شناسه به‌تنهایی مجوز دسترسی ایجاد نمی‌کند.
3. هر افشای داده باید هدف، دامنه، مدت و مبنای روشن داشته باشد.
4. هوش مصنوعی حق تصمیم مستقل درباره سرنوشت کودک یا خانواده را ندارد.
5. اعتماد هویتی میان چند Provider مستقل توزیع می‌شود.
6. بیومتریک فقط روی دستگاه/Authenticator برای فعال‌سازی کلید استفاده می‌شود و وارد CPIMS+ یا AI نمی‌شود.
7. هر دامنه داده شناسه مستعار مستقل خود را دارد و شناسه جهانی کودک تعریف نمی‌شود.
8. AI فقط حداقل داده لازم و در صورت امکان Derived Attribute دریافت می‌کند.
9. دسترسی حساس باید قابل ممیزی و اعتراض باشد.
10. پیش از هر استفاده از داده واقعی، معماری باید با داده مصنوعی Red Team و ارزیابی مستقل شود.

## مدل هویت

مددجو ابتدا روی یک Authenticator امن به صورت محلی احراز بیومتریک می‌شود. سپس سه Provider مستقل Assertion رمزنگاری‌شده صادر می‌کنند. Trust Gateway تنها وقتی Session معتبر ایجاد می‌کند که حداقل دو مورد از سه Assertion معتبر باشند.

این قاعده 2-of-3 یک کنترل اختصاصی پروژه است و الزام NIST نیست.

در reference implementation فعلی، اعتبارسنجی issuer، audience، nonce، freshness، expiration، replay و subject binding مدل شده و یک Provider به‌تنهایی نمی‌تواند Session ایجاد کند. این کد برای PoC است و جایگزین OIDC/FIDO/WebAuthn و مدیریت کلید Production نیست.

## رضایت و مجوز قانونی

Authentication و Consent از هم جدا هستند و Consent نیز با مجوز قانونی یکی نیست.

اثر انگشت یا Face ID فقط نشان می‌دهد چه کسی عمل را انجام داده است؛ به‌تنهایی ثابت نمی‌کند که رضایت آگاهانه و بدون فشار بوده است.

برای همین Consent باید شامل توضیح قابل فهم، هدف، سطح داده، مدت دسترسی و امکان لغو باشد. برای L3 Step-up Consent لازم است.

برای L4، رضایت به‌تنهایی مجوز فنی ایجاد نمی‌کند؛ یک Grant حقوقی/قضایی/قانونی یا اضطراری محدود به همان پرونده، هدف، عملیات و زمان لازم است. قاضی یا مقام قضایی در این مدل Superuser نیست.

## طبقه‌بندی داده

- **L1:** داده عملیاتی حداقلی
- **L2:** اطلاعات اجتماعی و خانوادگی حساس
- **L3:** سلامت، خشونت، سوءاستفاده، روان‌شناختی و داده بسیار حساس
- **L4:** اطلاعات استثنایی که افشای آنها می‌تواند آسیب شدید، اجبار یا سوءاستفاده نهادی ایجاد کند

L4 یک سطح Superuser نیست. Reference policy فعلی Bulk Export در L4 را رد می‌کند.

## AI

AI مجاز است جست‌وجو، خلاصه‌سازی، مقایسه، ارائه شواهد، توضیح، پیشنهاد و اعلام عدم قطعیت انجام دهد.

AI مجاز نیست به‌صورت مستقل بازپیوند خانواده را تأیید یا رد کند، کودک را از خانواده جدا کند، خدمات را قطع کند، دسترسی حساس را مجاز کند یا اقدام قضایی/امنیتی ایجاد کند.

AI مستقیماً به Database، Identity Vault یا Storage سازمانی وصل نمی‌شود. یک Context Builder پس از تأیید Policy Engine فقط داده حداقلی را با یک AI Context Token موقت در اختیار مدل قرار می‌دهد. Reference implementation فعلی ورود مستقیم نام، کد ملی، تلفن، ایمیل، آدرس دقیق، biometric و Case Anchor به AI context را رد می‌کند.

## Audit

Audit باید مستقل از دسترسی عادی اپلیکیشن باشد. PoC فعلی یک زنجیره tamper-evident روی eventهای مستعار ایجاد می‌کند و تغییر در رکورد قبلی را تشخیص می‌دهد. این فقط اثبات مفهوم است؛ Production به Audit Store مستقل و کنترل دسترسی جدا نیاز دارد.

## NIST

این پروژه ادعای NIST Certification یا NIST Compliance ندارد.

معماری با برخی اصول و انتشارات NIST هم‌راستا طراحی شده است، از جمله خانواده SP 800-63-4، Zero Trust Architecture، SP 800-53، Cybersecurity Framework، Privacy Framework و AI RMF.

جزئیات در `NIST_MAPPING.md` آمده است.

## وضعیت تست

GitHub Actions پروژه، Overlay فارسی را روی نسخه pinned Primero می‌سازد، key coverage را بررسی می‌کند، patch مربوط به `fa-IR` و RTL را اعمال می‌کند و تست‌های reference security را اجرا می‌کند.

موفق شدن این CI به معنی Production-ready یا Secure Deployment نیست؛ فقط نشان می‌دهد پیاده‌سازی مرجع فعلی به‌صورت قابل بازتولید build/test می‌شود.

## محدودیت مهم

هیچ معماری نرم‌افزاری نمی‌تواند تضمین کند که قدرت قانونی، سازمانی یا سیاسی هرگز از داده سوءاستفاده نخواهد کرد.

هدف این پروژه واقع‌بینانه‌تر است: دشوارتر و قابل‌کشف‌تر کردن دسترسی گسترده، پنهانی، غیرضروری، تک‌نفره و بدون پاسخ‌گویی.

## هدف انتشار عمومی

این پروژه برای مالکیت انحصاری دانش ساخته نشده است. هدف، ایجاد دانش فنی و اخلاقی قابل خواندن برای انسان و ماشین، قابل نقد، قابل توسعه و قابل استفاده عمومی در چارچوب مجوز پروژه است.

نسخه اصلی انگلیسی و ساختار فنی در فایل‌های ریشه مخزن قرار دارند و `PROJECT.yaml` مرجع machine-readable پروژه است.
